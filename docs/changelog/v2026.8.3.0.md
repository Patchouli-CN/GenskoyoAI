# GensokyoAI v2026.8.3.0 更新日志

发布日期：2026-08-03

## 一句话总结

NoneBot2 QQ 适配器从零落地为生产可用的 QQ 机器人：群聊陪聊、到点提醒、
掉线自愈、群友印象、复读防护一应俱全；角色「内心」系统（八维情绪、对话欲、
长期思考、定期记忆蒸馏）与「工作 + 语义」两层记忆收口成型；全项目结构优化
净减约 1100 行。

## 新增功能

- **NoneBot2 QQ 适配器**（`uv sync --extra nb2` 后 `python -m GensokyoAI.backends.nb2`）。
  QQ 群 / 私聊桥接到 Runtime 多租户（每群、每个私聊用户一个独立角色会话，
  租户隔离、资源闸、幂等账本全部来自 RuntimeService 本身）；适配器与 Runtime
  同进程（进程内 `RuntimeHost`），无第二个进程、无鉴权配置、无 HTTP 绕路。
  部署与行为详见 [`docs/nb2_adapter.md`](../nb2_adapter.md)。
  - **复读防护（烦躁模型）**：同一用户连续复读/刷屏时角色会烦——连击注入
    厌烦（回复转冷淡），再犯当面表态后进入冷却「不理」；冷却期复读零 token
    丢弃，有新意则由 LLM 以角色性格裁决：消气原谅 / 破例回一句 / 继续不理。
  - **群友印象**：与新群友首轮交谈后自动用一次性脱稿生成第一人称「第一印象」，
    之后该群友发言时印象随消息注入，角色「认识」老熟人；角色也可经
    `update_member_impression` 工具自行更新印象。
  - **引用原文**：消息里的引用段（reply）取回被引用内容拼进上下文，角色
    看得到「你认识她吗」指的是谁。
  - **说话人标记 + 待发合并**：群聊消息带 `【昵称】` 前缀；多人同时 @bot
    （或一人快速连发）时消息攒成一批、一次生成一条回复同时回应所有人，
    不再交替回复，也只烧一份 token。
  - **到点提醒**：对 bot 说「3 分钟后提醒我」「明早 8 点喊我」「不要提醒了」
    即可。注意力管线判定请求/取消后**代办登记**（不经工具调用，重启不丢）；
    到点角色用自己的口吻 @ 到人交付；30s tick，一分钟内必达。
  - **NapCat 掉线守护**：账号被踢下线或协议端断连时自动恢复——安全清理
    （绝不盲杀个人 QQ）→ 快速登录重启 → WS 回连确认；QQ 号未知时照常启动
    走终端扫码登录（扫一次码即可）；适配器启动后 10 秒宽限内未连接也会
    自动拉起 NapCat，不用手动先启动。冷却期 + 每日上限 + 哨兵告警防无限
    重启激怒风控；仅 Windows 生效。
  - **指令体系**：`/help`、`/quota`、`/status`，走框架 commands 四级权限
    （`VISITOR < USER < ADMIN < OWNER`，未声明权限的指令默认仅主人）；
    未注册指令与权限不足对用户完全静默。`/status` 展示负载水位、额度健康、
    开户数、处理中、闸门用量、内心思考延迟、复读防护、记忆规模、版本与
    运行时长。
  - **回复 @**：该 @ 谁由注意力 `reply_focus` 种类做**因果判定**（这轮谁
    冲着 bot 来：提问/委托/等回应）——有焦点才 @，普通闲聊不 @；文本中的
    `@昵称` 一律转成 QQ 真 at（能提醒到人），模型自己写的 @ 与程序 @
    自动去重。工作记忆里助手消息也带 `@昵称` 标记，角色分得清「我刚才
    那句话是回谁的」。
  - **回复风格**：默认 QQ 群聊风格（简短口语、每句一行、不写动作），按行
    拆成多条短消息依次发送；`GSK_NB2_EXTRA_PROMPT` 可当轮注入自定义要求；
    发送前确定性清洗 RP 标记（`*动作*`、`「」`）兜底。
- **AttentionThings 注意力事务管线**（`core/agent/attention.py`）：候选预筛 →
  一次性 LLM 判定（脱稿不进会话）→ 命中代办。`AttentionKind` 可注册扩展，
  与具体事务零耦合；nb2 已内建 `reminder`、`reply_focus` 两个种类。
  判定失败一律静默降级为普通回复，绝不拖垮主回复。
- **定期记忆蒸馏**：每 `memory.distill_turns`（默认 10）轮对话后，角色以
  第一人称从近期对话提炼 0~3 条「值得记住的事」（事实/偏好/关系/情感重量
  事件，明确不记寒暄琐事）写入语义记忆，替代已删除的「AI 主动记忆工具」。
- **话题淘汰**：冷话题按半衰期热度**读取时惰性隐藏**（`memory.decay`，
  pin 免疫、重提即复活）；`memory.semantic_max_topics`（默认 50）写入侧
  硬上限，淘汰回忆权重最低的非 pin 话题。
- **八维情绪状态机**（`core/agent/emotion.py`）：anger/sorrow/fear/happy/
  love/surprised/disgust/shame 持续心情，挂对话欲评估顺带自评（零新增
  LLM 调用），随时间向角色基线衰减。情绪驱动三处：回复语气注入、对话欲
  阈值调制（消沉少言、气头易呛）、行为倾向（心情好话多、嫌弃冷淡）。
  角色卡新增 `emotion_baseline` 字段。
- **角色卡四维心情权重** `motivation_weights`：表达欲/情感驱动/关系需求/
  情景相关性各维度权重可按角色定制（默认通用人格基线，不写行为不变）。
- **HalfCompletionMessage**：流式响应中断时，没说完的半截回复计入中间
  状态，下一轮让角色接着说完（错误标记不进模型上下文），说完按普通
  消息处理——角色不再对用户已看到的半句话失忆。
- **OneShotGenerator 一次性脱稿生成**（`core/agent/oneshot.py`）：不建租户、
  不进任何会话与记忆的短文本生成通道（第一印象/破例判定/注意力判定）。
- **额度查询与成本计量**：`Provider.get_quota()` 可选能力（已实现 Moonshot
  余额端点）；ModelClient 按单价 × usage 采样单次成本（`model.price_*`，
  支持 cache_read/cache_write 缓存分项计价），`/status` 展示日耗。
- **HealthCenter 健康总监控**（`core/health.py`）：额度健康判定收口 yaml
  `health:` 节静态阈值（🟢/🟡/🔴/🟣/⚫ 五级 + 健康指数），重启不漂移；
  日耗计量仅展示不参与判定。
- **适配器公共约定**：`GensokyoAI.adapters`（`RuntimeAdapter` 抽象基类 +
  `run_adapters`/`serve_adapters` 组装入口，Ctrl+C 逆序停止并统一保存）；
  `RuntimeHost` 升格 `runtime/host.py` 为适配器公开契约；console/nb2/Web
  统一继承。第三方包实现同一基类即可接入。
- **适配器私有配置目录** `config/{adapter}/` 约定 + 首次运行播种：
  `config/nb2/local.env` 与 `config/local.yaml` 不存在时自动从模板生成
  （只播种一次，绝不覆盖）。
- **日志 TRACE 级别**：`LogLevel` 新增 TRACE——逐条 IO/内容细节归 TRACE，
  流程决策点留 DEBUG；`log_level: DEBUG` 显著变安静，全细节用 TRACE。
- **Provider 校验元数据化**（`core/agent/providers/specs.py`）：provider 校验
  知识（要不要 key、私网地址、不支持字段等）收敛为单一事实源，新增
  provider 登记一行即可。

## 行为变化

- **记忆三层收口为两层**：情景记忆（episodic）子系统整体删除——其写入
  路径从未接线，「历史压缩摘要」职责已被定期记忆蒸馏实质接替。旧配置键
  `memory.episodic_*` 仅给迁移警告不报错（指向 `memory.distill_turns`）。
- **「AI 主动记忆」工具删除**：`remember`/`recall`/`update_memory` 工具与
  REMEMBER/RECALL/THINK 动作子系统移除（实测见啥记啥，语义记忆全变噪音）。
  语义记忆仍自动检索注入提示词；`builtin_tools` 名单里的 `"memory"` 项
  需移除（配置诊断会提示）。
- **工作记忆裁剪真正生效**：`working_max_turns` 此前形同虚设（长会话
  token 无界增长），现按轮数裁剪并丢弃头部孤儿 tool 消息；工具调用的
  前言文本不再重复入记忆（省一份上下文）。
- **web_search 服务改按 Actor 注入**：多角色/多租户不再「后初始化者胜」
  互相覆盖配置。
- **主动发言更克制**：对话欲评估新增节奏规则（对方热聊时把话头让给对方，
  修「你说一句它回两句」）；连续主动发言上限对思考冲动路径同样生效；
  主动消息提示词去机制化（不再漏出「主动定时器到点了」这类幕后词汇）。
- **租户上限改 LRU 休眠驱逐**（`resource_control.tenant_max_agents_per_user`，
  默认 32）：满员不再永久堵死新群——最久未活跃租户优雅休眠（数据全保留，
  再发言自动唤醒），全部繁忙才报 `agent.limit_exceeded`。
- **Runtime 热路径异步化**：幂等账本与会话读写全链路 async（此前每条消息
  同步全量重写账本两次）。
- **World 模式 `/know` `/meta` `/attention` 提示词命令真正注入角色回合**
  （此前静默失效）。
- **日志默认更安静**：常规运行建议 `log_level: INFO`，排查用 `DEBUG`，
  全量细节用 `TRACE`。
- **额度健康判定改静态阈值**：动态阈值方案（按消耗速率算阈值）经两轮
  迭代后取消——重启即漂移、判定无意义；计费计量保留，仅作 `/status` 日耗
  展示。

## 修复问题

- **记忆蒸馏在 nb2 从未触发**：Runtime 每条消息都重新 activate 当前会话，
  `resume_session` 不短路导致蒸馏轮次计数每条消息被清零（永远到不了阈值）。
  现 `resume_session` 对当前会话幂等；连带修复半截续说状态被每条消息清空、
  语义记忆每条消息重建（日志噪音）。
- **多人同时 @bot 交替回复**：改待发合并（见上），一轮回复同时回应所有人。
- **双 @**：模型自己写的文本 @ 与程序真 at 重复显示——现按形态剥除开头
  文本 @ 串（含模型写错名字的变体），只留程序 at。
- **工具注册表全局泄漏**：适配器/租户闭包工具会被之后新建的 ToolRegistry
  吸进无关 Agent（同名互踩）；改实例级构建。
- **僵尸提醒堵配额**：重试耗尽的提醒永久计入待办数，可堵满租户提醒配额；
  现 `due()` 顺带清除。
- **第一印象任务弱引用**：`create_task` 未持强引用可能被 GC 提前回收，
  成员永久占位不再生成印象；现强引用持有。
- **episodic 旧配置键崩溃**：删除子系统后校验层只警告、加载层未剔除，
  旧配置直接裸 TypeError；现按删除清单剔除后仅警告。
- **租户关闭日志无身份**：多租户关停时同款日志分不清哪户——Agent/
  ThinkEngine/后台/保存协调器日志带租户标签。
- **守护拉起的 NapCat 控制台中文乱码**：启动命令补 `chcp 65001`。
- **会话文件原子替换 WinError 5**（Windows 文件占用偶发拒绝访问）：
  退避重试。
- **持久化完成事件 session_id 恒为 None**：改现查现报。

## 已废弃但仍兼容

- `memory.episodic_threshold` / `memory.episodic_summary_model` /
  `memory.episodic_keep_recent`：随情景记忆子系统删除废弃，旧配置仅给
  `config.field.deprecated` 迁移警告（不报错），指向 `memory.distill_turns`。
- `builtin_tools` 中的 `"memory"` 项：记忆工具已移除，名单里保留该项
  会在诊断中提示，请删除。

## 已移除或破坏性变化

- **情景记忆（episodic）子系统**：`memory/episodic.py`、相关配置键、事件
  与提示词全部删除。无持久化数据需要迁移（该子系统从未真正写入过数据）。
- **记忆工具与 REMEMBER/RECALL/THINK 动作**：见「行为变化」。替代方案 =
  定期记忆蒸馏（自动写入）+ 检索自动注入（读取侧不变）。
- **`SystemEvent.MEMORY_WORKING_ADDED`**：内部事件，无发布者无订阅者，删除。
- **`GSK_NB2_QUOTA_WARN` / `GSK_NB2_QUOTA_CRIT` env 键**：额度阈值改 yaml
  `health:` 节（`quota_warn_yuan` / `quota_crit_yuan`）。
- Runtime 协议无破坏性变化（major 保持 2），不需要客户端迁移。

## 数据迁移与升级提醒

- 无 schema version 变化；会话、语义记忆（topics.json）格式不变。
- nb2 适配器数据文件（`nb2_data/sessions.json` / `known_members.json` /
  `reminders.json`）为本版本新增，原子写入、损坏降级为空表。
- 旧配置里的 `memory.episodic_*` 键仅警告不报错，可按警告提示删除。

## 安装与依赖变化

- 新增可选依赖组 `nb2`：`nonebot2[fastapi]>=2.4` + `nonebot-adapter-onebot>=2.4`；
  不安装不影响 CLI / Runtime 正常使用。
- QQ 协议端推荐 NapCat（go-cqhttp 已停止维护）；守护功能仅 Windows 生效。
- Python 版本要求不变（>= 3.14）。

## Runtime / 客户端兼容性

- Runtime 协议版本：2.1.0（major 2），与 v2026.7.30.0 一致，无迁移负担。
- methods 变化：`initiative_timer.update` 新增 `enabled` 参数（进程内开关，
  加法兼容；params schema 签名驱动自动生效）。无删除方法。
- capabilities 变化：无。
- 返回字段变化：`get_system_status`（进程内 RuntimeHost 契约）大幅扩展
  （gates/load_level/cost/memory/latency/uptime），均为增量键；`tenants`
  统计不再含 `meta` 键（nb2-meta 元租户已删除，由 OneShotGenerator 取代）。
- 废弃 methods / fields：无（本版 Runtime 层）。
- breaking changes：无。

## 已知问题

- 全项目大调查（`ignore/CODE_INF.md`，本地档案）尚有数十条低危可疑点
  未修（已修条目已在档案内标记）；多为边界条件与防御缺口，不影响主链路。
- 合并批的幂等键取批次首条消息：QQ 对批内后续消息的极端重投无法被幂等
  账本去重（概率极低）。
- NapCat 掉线守护仅 Windows 生效；其他平台只告警。
- 适配器不解析图片/语音/合并转发，只处理纯文本；全 bot 共用一个角色
  （暂无按群切换）。
