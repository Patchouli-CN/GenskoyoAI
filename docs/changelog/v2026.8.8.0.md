# GensokyoAI v2026.8.8.0 更新日志

发布日期：2026-08-08

发布渠道：GitHub Alpha prerelease（wheel + sdist）

## 一句话总结

这是自上一公开版本 `v2026.7.14.0` 以来的累计 Alpha prerelease：Runtime 完成面向单节点远程多用户服务的一次协议主版本收口，多角色 GensokyoWorld、NoneBot2 适配器、两层记忆与情绪系统落地，同时补齐幂等、并发、迁移、事件恢复和安全边界。

## 主要新增功能

- **远程多用户 Runtime v2**：HTTP、WebSocket 和 SSE 统一采用 `user_id -> agent_id -> session_id -> message_id` 资源层级；JWT `sub` 作为稳定用户身份，支持 `read`、`chat`、`admin` RBAC。
- **可恢复的消息写入**：会话写操作使用 `expected_revision` 乐观并发控制，消息发送使用 `idempotency_key`；Provider 调用前写入持久化操作账本，可用 `message.status` 查询断线请求终态。
- **Runtime 可发现契约**：`runtime.info` 暴露协议、能力、方法、参数 schema、结果 schema 完整度、废弃项、breaking changes、传输信息和当前禁用方法；新增 readiness、优雅 drain 与默认关闭的远程管理面。
- **持久事件与媒体入口**：租户事件具有稳定 `event_id` 和单调 `sequence`，SSE/WS 支持游标回放；远程媒体使用 multipart 上传并按用户与 Agent 隔离。
- **GensokyoWorld 多角色编排**：多个角色共享舞台和公开剧本，同时保持私有会话与记忆；Director 负责选角、换场和把发言权交还用户；提供 `world.*` RPC、控制台模式、持久化、恢复与视角记忆投影。
- **NoneBot2 QQ 适配器**：群聊与私聊映射到独立 Runtime 租户，包含提醒、掉线守护、群友印象、复读防护、回复焦点、消息合并、状态与额度指令。
- **角色内在状态**：八维情绪、四维对话欲、主动发言节奏、长期思考和定期记忆蒸馏形成统一链路。
- **两层记忆模型**：工作记忆按轮裁剪；语义记忆支持蒸馏、检索、增删改查、图谱、冷话题衰减和容量淘汰；新增 `memory.add` RPC。
- **工具与知识检索**：新增 `fetch_url`、权威知识站点选路、最多两轮工具追问，以及群黑话自动学习。
- **Provider 与多模态**：OpenAI、Responses、Claude、Gemini 等 Provider 的 usage、流式结束块、图片和多模态内容转换进一步统一。

## 行为变化

- reasoning 默认公开。客户端应把 `reasoning_content` 与最终 `content` 分开展示，并自行应用可见性策略。
- WebSocket 流式请求先返回包含 `stream_id` / `generation_id` 的 start acknowledgement，再发送内容帧。
- `session.list` 与 `session.messages` 改为游标分页结果对象。
- HTTP/WS 默认禁用 `runtime.shutdown`、`dependency.install`、角色包导入导出等远程管理方法；需要在受信任管理网络显式开启。
- 主动发言改为 ThinkEngine 四维打分加阈值判定，删除强制兜底和累积器；AI 不想说话时不再强行生成。
- 情景记忆子系统和主动记忆工具退役，长期信息统一由语义检索和定期蒸馏接管。
- 输出清洗区分投递文本与记忆文本，并移除整行舞台指示、伪说话人标签、独立分隔线及内部 DEBUG 分类残留。
- GenerationGuard 为长期思考、蒸馏和回合请求绑定会话代际；会话切换后迟到任务不再写回新会话。

## 可靠性与安全修复

- 修复同键并发导致双生成、长会话成功结果误记 failed、断线后操作永久 pending，以及回滚覆盖旧消息等幂等账本问题。
- 修复租户创建 TOCTOU、在途删除、等待锁期间被 LRU 驱逐和单租户损坏拖垮进程等多用户生命周期问题。
- 修复 SaveCoordinator 跨会话迟到回调、worker 崩溃后 pending 卡死、World 段落中断不落剧本和主动段落漏存档。
- 修复 SSRF 对尾点、短写、十进制、十六进制和 IPv4-mapped 地址的绕过。
- 修复 WebSocket 心跳异常清理、事件订阅泄漏、同步文件/子进程阻塞事件循环和 fire-and-forget task 被回收。
- 修复流式 usage 末块被跳过、多模态 parts 结束判断 TypeError，以及工具第二轮调用被丢弃导致“搜了但不回”。
- 事件与日志脱敏改为精确敏感名/后缀匹配，避免泄漏凭据，同时不再误抹正常计量字段。

## Deprecated（仍兼容）

- 非命名空间 legacy RPC（如 `init`、`send_message`、`list_sessions`）继续可用；新客户端必须使用 `runtime.info.method_specs[].replacement` 指向的命名空间方法。
- `initiative_timer.hesitation` / `initiative_timer.hesitation.set` 继续返回退役载荷，不再修改 Agent 状态。
- 所有当前 legacy RPC 的最早移除版本统一为 Runtime protocol `3.0.0`；本次不删除 legacy 方法。

## 已移除或破坏性变化

Runtime protocol 从上一公开版本的 `1.1.0` 升至 `2.2.0`，major 从 `1` 升至 `2`。协议 1 客户端不能假定直接兼容，必须至少处理以下变化：

1. RPC 失败使用顶层 `ok=false` 与顶层 `error`，不再嵌套在 `result.ok=false`。
2. WebSocket 流式请求增加 start acknowledgement。
3. `runtime.info.protocol` 表示共享 RPC 协议；具体传输从 `runtime.info.transports` 发现。
4. reasoning 默认公开。
5. 网络 Agent/Session 操作要求显式 `agent_id` 与 `session_id`。
6. 会话写操作要求 `expected_revision`；消息发送与状态查询要求稳定 `idempotency_key`。
7. `session.list` / `session.messages` 返回分页对象，不再返回裸列表。

旧的 `initiative_timer.fallback_*`、`hesitation_*`、`drive_*` 累积配置和 `memory.episodic_*` 配置已退役；配置诊断会给出迁移提示。`remember` / `recall` / `update_memory` 主动记忆工具已移除。

## 客户端迁移步骤

1. 启动后先调用 `runtime.info`，拒绝未知 `protocol_major_version`；本版应为 `2`。
2. 通过 `methods`、`method_specs`、`capabilities` 和 `active_transport.disabled_methods` 做能力发现，不硬编码可用方法。
3. 建立或列出 Agent，保存返回的 `agent_id`；会话操作保存 `session_id` 与最新 `revision`。
4. 每次写会话携带 `expected_revision`。冲突时重新读取权威状态后合并。
5. 每次消息发送生成 1-128 字符的 `idempotency_key`；网络重试复用同一个键。
6. WS 先读取 start acknowledgement；断线后调用 `message.status`，再读取 `session.messages` 恢复，不尝试续接 token 流。
7. 按分页对象消费 session/messages，并将 reasoning 与最终正文分开展示。

完整契约见 [`docs/runtime_api.md`](../runtime_api.md)。

## 数据迁移与升级提醒

- session schema 从 `1` 升至 `2`：旧会话首次读取时自动补 `revision`、稳定 `message_id` 和消息 revision，并保留未知扩展字段；迁移前文件保存为 `.bak`。
- memory schema 保持 `2`，config、session export 和 character package schema 保持 `1`。
- 新增独立 world session schema `1`。
- 更高且未知的 schema version 不会被静默降级覆盖；Runtime 会返回诊断并保留原文件。

## 安装与依赖变化

- Python 最低版本仍为 3.14。
- 核心依赖 `ayafileio` 最低版本升至 `1.4.8`。

- wheel/sdist 现在包含模板、角色、场景和文档资源；源码 checkout 与安装包使用同一资源查找逻辑。
- 本次仅发布 GitHub wheel 与 sdist，不上传 PyPI，不捆绑 HakureiTerminal。

## 已知限制

- 默认文件后端支持单节点远程多用户服务，不承诺多节点一致性；多节点需要数据库与共享对象存储。
- 生成 token 流不支持跨连接续传，客户端应通过操作状态和权威会话恢复。
- Provider SDK 仍按 extra 可选安装；wheel 不强制捆绑所有 Provider。
- 项目仍为 Alpha，协议 2 内会优先采用兼容加法；未来删除 legacy RPC 时将进入 protocol 3。
