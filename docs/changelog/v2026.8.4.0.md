# GensokyoAI v2026.8.4.0 更新日志

发布日期：2026-08-04

## 一句话总结

「外置注意力」体系扩军：群黑话矿工（jargon）让角色逐渐听得懂群里的黑话，
`fetch_url` + 权威知识站点让角色查领域知识不再靠脑补和看天吃饭的爬虫；
OOC 管线经两轮实机审查连修五个逻辑漏洞；「搜了但不回」的空回复根因
（第二轮工具调用被丢弃）已修复。

## 新增功能

- **群黑话矿工（AttentionThings `jargon` 种类）**：每个群按缓冲量（默认 40 行）
  与冷却（默认 30 分钟）触发一次 LLM 判定，挑「这个群特有的、外人看不懂的
  词/梗/固定用法」，词条自动写入该群语义记忆（话题名=黑话词，内容带
  「可能待考证」防幻觉释义）——之后群友再用这个词，释义会随现有检索注入，
  角色逐渐「听得懂」。私聊不学；已学过的话题名不重复学习。
  配置：`GSK_NB2_JARGON`（默认开）/`GSK_NB2_JARGON_MIN_LINES`/`GSK_NB2_JARGON_COOLDOWN`。
- **`fetch_url` 工具 + 权威知识站点**：内置网页抓取工具（aiohttp，SSRF
  校验、HTML 剥标签、4000 字截断）；`tool.web_search.knowledge_sites` 配置的
  站点表（site + desc）渲染进每轮工具指令，模型自行选路——领域知识
  （角色/作品/设定）优先 fetch_url 权威站（MediaWiki 可用 api.php 搜词条），
  无关内容才走 web_search。抓取失败只给模型一句干净人话，URL/超时等
  技术细节只进日志（不会再被角色念出来）。启用：`tool.builtin_tools` 加
  `"fetch_url"` 并配置 knowledge_sites（如 thbwiki.cc）。
- **`memory.add` RPC**：向当前会话语义记忆写入一条（适配器知识学习通道；
  topic_name 命中既有话题直接归入）。Runtime 协议版本随之升为 **2.2.0**
  （major 保持 2，纯加法，客户端无迁移负担）。
- **工具调用详情日志**：`检测到 N 个工具调用: 名称列表`（INFO），每次调用
  DEBUG 记 `name(arguments)` 与执行成功摘要（截断预览），内容全文仍 TRACE。

## 行为变化

- **OOC 判定轮数耗尽不再投递未判定版本**：全程跟踪已判定版本分数，轮尽
  退回最低分版（可能是原稿——「越修越糟」不再发生）；最后一轮仍超标不再
  做无人能判定的重写（省一次调用）。预检照抄重写后也进有界判定循环。
- **硬否决按最差分计**：`copied_inner_monologue` 的版本在 best-of 回退中
  按 1.0 分计，不会再被最低分回退捞回来。
- **群聊合并批不再被 OOC 误判**：本轮发言者名单透传判定/重写——judge 知悉
  「分头回应多人、多个 @ 是场景需要，不算模板化」，rewrite 被硬约束
  「必须保留对每一位的回应，不得合并或省略」。
- **自我复读预检**：候选回复与自己近期回复雷同（整体相似或整段照搬，
  换名复述也算）直接重写——「把问题当新问题重新答」。短回复豁免防误伤。
- **工具追问轮**：模型看完工具结果想再查一次时，第二轮 tool_calls 照常
  执行（最多 2 轮），修复「搜了但不回」的空回复（此前第二轮 tool call
  直接丢弃、无正文触发兜底文案）。
- **OOC 判定跳过 World 回合与流式实时消费**：舞台旁白不会被 QQ 口语标准
  误改；流式已投递内容不再被重写（避免「用户看到的 ≠ 角色记住的」分叉）。

## 修复问题

- **幂等账本长会话误记 failed**（高危回归）：工作记忆满员裁剪后新
  assistant 落在索引水位线下，每次成功生成被记 failed（不盖章、重试报错）。
  改按内容定位本轮 assistant。
- **保存链路三修**：`SaveCoordinator.reset()` 接回会话切换（新会话自动
  保存不再被旧基线静默跳过）；保存完成回调按会话认领（跨会话迟到结果
  不再清新会话 pending）；PersistenceWorker 兜底路径崩溃（曾致 pending
  永久卡死）。
- **SSRF 校验编码变体绕过**：`169.254.169.254` 的尾点/短写/十进制/
  十六进制/v4-mapped 写法此前全部放行，云元数据直达；现按 inet_aton
  语义归一化后判定。
- **knowledge_sites 加载即炸**：msgspec 构造不深度转换 list 项，yaml 项
  留在 dict 导致指令渲染取属性时报错；现显式转换为 struct。
- **红测试 ×4**：SSRF 测试对齐模板 provider 变更；配置目录测试 import
  随迁。

## 已知问题

- 「问时不搜」：主模型工具纪律仍非百分之百可靠（已有硬指令版知识站点
  选路；更彻底的「lookup 注意力代办搜索」在评估中）。

  兜底下偶发单引擎报错属预期。
