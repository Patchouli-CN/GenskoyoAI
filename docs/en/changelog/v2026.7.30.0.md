# GensokyoAI v2026.7.30.0 Release Notes

Release date: 2026-07-30

## TL;DR

GensokyoWorld multi-character orchestration is fully landed: from "playing one character" to "one model performing an entire play" — multiple characters share one stage while a Director decides who speaks each turn. The console `--world` flag and the Runtime `world.*` RPCs are available end to end. Single-character mode behavior is unchanged.

## New Features

- Added the GensokyoWorld multi-character world (off by default; enable via `world.enabled` or `--world`).
  - User impact: multiple characters can now act on one stage. All characters share a single model (no cost multiplication) while keeping fully independent sessions, working memory, and long-term memory. A Director decides `continue` / `switch` / `wait_user` based on story, presence, and dramatic timing — this is not a round-robin group chat.
  - Action required: none; it is off by default. To try it, run the bundled example (Marisa × Remilia × Scarlet Devil Mansion): `uv run -m GensokyoAI.cli.main --config config/world_example.yaml`.
- SharedTranscript and WorldStage: public dialogue is recorded per scene, and movement is managed centrally; with `user_follows_current_actor` the user automatically follows the current actor across scenes.
- Perspective memory projection: after each performance segment, the world writes a "my own perspective" memory for every character present (the same event — Marisa remembers a triumph, the mansion's owner an intruder). Characters who were absent learn nothing. Disable with `world.project_perspective_memories: false`.
- World initiative loop: exactly one initiative timer per world; after each segment the world plans the next story push, and when it fires the Director picks a speaker from whoever is present right then. User messages always take priority and cancel pending intents. Single-character initiative timers are unchanged.
- Drive-based initiative model (`initiative_timer.drive_enabled`, off by default): short-term thinking now evaluates four motivation dimensions (expression / emotional drive / relational need / situational relevance); pure-arithmetic accumulation crosses a threshold before the character speaks up — zero token cost across silent turns. Mood decays with asymmetric half-lives, speaking vents pressure, and state persists with the session.
- World session persistence and resume: stage, shared transcript, and each actor's private session are archived independently (`world session schema v1`); resume completely via `--resume` or `world.session.resume`. Roster differences surface as structured diagnostics — characters are never silently mixed up.
- Console World mode: enter with `--world` (or `world.enabled: true`); dynamic speaker prefixes (`Marisa:` / `Patchouli:`), scene-move hints, and live initiative display; new `/world`, `/roster`, `/stage`, `/transcript` commands.
- Runtime `world.*` RPCs (14 methods): `world.init` / `world.start` / `world.send_message` / `world.send_message_stream` / `world.state` / `world.roster` / `world.transcript` / `world.move` / `world.session.create` / `world.session.list` / `world.session.resume` / `world.session.delete` / `world.session.export` / `world.shutdown`.
  - Client impact: WebSocket `world.send_message_stream` streams `world.actor.started` / `world.actor.chunk` / `world.actor.completed` / `world.waiting_user` / `world.finish` frames; `runtime.info` adds the `world.orchestration` capability; event subscriptions add the `world` category (8 `world.*` events, included in `runtime_observable`).
- The roleplay system-prompt scaffold gained rule 6: examples inside the prompt are no longer treated as personality reference — actual personality follows the character card (reduces small models acting example tone as character voice).

## Behavior Changes

- The forced initiative fallback chain is removed: `initiative_timer.fallback_on_no_schedule` and 3 related config keys are gone from the schema — when the AI decides not to speak, nothing is forced. Legacy keys are silently dropped and reported as migration warnings (not errors); initiative timer event payloads drop `fallback_on_no_schedule` / `is_fallback`, and `source` gains `"drive"`.
- Runtime event redaction is unified project-wide to `sanitize_event_payload` with the `[REDACTED]` placeholder (the Runtime event egress previously used `[redacted]`); the redacted field set grows to cover `auth`, `passwd`, `headers`, `extra_headers`, and `password` substring matching — strictly safer.
  - Client impact: if your client matched the old `[redacted]` placeholder exactly, switch to `[REDACTED]`.
- `dependency.install` now clamps its `timeout` to the `resource_control.dependency_install_timeout_seconds` ceiling and runs pip on a worker thread instead of freezing the event loop.
- Session/memory files with a higher unknown schema version are no longer silently downgraded, aligning with the World archive contract of "no silent downgrade" (returned as-is after a warning).
- Compatibility: none of the above changes single-character behavior; legacy sessions, memories, and character files are untouched.

## Fixes

- Fixed idempotency ledger records stuck in `pending` forever when a WebSocket disconnect/cancel landed inside the send window: the streaming frame pump now deterministically closes the generator in `finally`, and the service layer converges `GeneratorExit` to `cancelled`. Retries with the same `idempotency_key` now see a terminal `cancelled` state instead of a permanent "in progress".
  - Affected: remote deployments with unstable networks or client-initiated stream cancellation.
- Fixed the `handle_ws` cleanup chain being cut short by heartbeat exceptions, leaking event subscriptions and stream tasks.
- Fixed one tenant's corrupt `operations.json` taking down the whole process at startup: tenant catalog loading is now isolated per tenant — corruption skips that tenant with a warning (no silent empty-ledger rebuild).
- Fixed `dependency.install` running a synchronous pip subprocess (up to 600s) inside the async path and freezing the entire event loop.
- Fixed response-generation races (orphan generations): results from timed-out/cancelled generations are no longer delivered.
- Fixed `topics.json` corruption silently wiping semantic memory (atomic replace + backup + quarantine).

## Deprecated but Compatible

- No new deprecations. Legacy non-namespaced RPC methods (`init`, `send_message`, etc.) remain deprecated with `remove_after` still `2.0.0`; see `runtime.info.deprecated_methods` for replacements.

## Removed or Breaking Changes

- The 4 forced-fallback `initiative_timer.fallback_*` config keys are removed (see "Behavior Changes"); legacy keys only warn and do not block startup.
- Runtime protocol `2.0.0` → `2.1.0` (major stays `2`): additive methods and capabilities only — no removals, no semantic changes, no major bump required.

## Data Migration & Upgrade Notes

- No data migration: session schema v2, memory schema v2, and config schema v1 are unchanged; the World archive is a new independent format (`world session schema v1`) that does not affect existing data.
- Legacy `initiative_timer.fallback_*` keys are dropped by the loader and reported via `DEPRECATED_FIELDS` warnings in `config.validate`; remove them at your convenience.

## Installation & Dependency Changes

- None: Python 3.14+ and the existing dependency set are unchanged; no reinstall needed.

## Runtime / Client Compatibility

- Runtime protocol version: `2.1.0`
- Runtime protocol major: `2` (unchanged)
- Supported clients: any client compatible with protocol major `2` keeps working unchanged; `world.*` is purely additive.
- Methods changed: added `world.init`, `world.start`, `world.send_message`, `world.send_message_stream`, `world.state`, `world.roster`, `world.transcript`, `world.move`, `world.session.create`, `world.session.list`, `world.session.resume`, `world.session.delete`, `world.session.export`, `world.shutdown`.
- Capabilities changed: added `world.orchestration`.
- Return fields changed: `runtime.info.methods` / `method_specs` list the new methods; the event contract adds 8 `world.*` events; the `world` event category is included in `runtime_observable`. Initiative timer payloads drop `fallback_on_no_schedule` / `is_fallback` and `source` gains `"drive"`.
- Deprecated methods / fields: none new.
- Compatibility notes: none new.
- Breaking changes: none new (protocol major stays `2`).

## Known Issues

- WorkingMemory is not yet trimmed (`max_turns` is currently ineffective), so very long sessions keep growing in context tokens; a "two-layer memory" simplification (working-memory trim + long-term semantic memory) is planned.
- The episodic compression subsystem is currently disabled (default configs are unaffected).

## Notes for Developers

- Code changes: new `GensokyoAI/world/` package (stage / transcript / director / persistence / memory_projector / initiative / world orchestrator), `core/dialogue_loop.py` and `core/initiative_scheduler.py` (dialogue-loop abstraction shared by single- and multi-character modes), `core/agent/drive_accumulator.py` (drive model); `RuntimeState` gains a `world` field (mutually exclusive with `agent`); console gains `backends/console/world_backend.py`.
- Architecture principles: single-character mode never pays for multi-character machinery; the Agent remains the source of conversational truth with World as an additive orchestration layer; Agents never share an EventBus — only the ModelClient and resource gates are shared.
- Test results: `uv run pytest -q` reports 609 passed (including targeted World tests at every layer); `uv run ruff check .` and `uv run pyright` are clean.
- Documentation: [`runtime_api.md`](../runtime_api.md) gained the World Orchestration API chapter; both READMEs and [`QUICKSTART.md`](../../QUICKSTART.md) gained multi-character sections.
- Release checklist: [`versioning.md`](../versioning.md) verified — package version, protocol version, changelog, and schema table are consistent.
