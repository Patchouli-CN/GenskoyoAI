# GensokyoAI v2026.8.8.0 Changelog

Release date: 2026-08-08

Channel: GitHub Alpha prerelease (wheel + sdist)

## Summary

This cumulative Alpha prerelease covers everything since the previous public version, `v2026.7.14.0`. The Runtime completes its protocol-major transition toward a single-node remote multi-user service; GensokyoWorld, the NoneBot2 adapter, two-layer memory, and emotion systems land end to end; and idempotency, concurrency, migration, event recovery, and security boundaries are hardened.

## Major Features

- **Remote multi-user Runtime v2**: HTTP, WebSocket, and SSE use `user_id -> agent_id -> session_id -> message_id`; JWT `sub` is the stable user identity with `read`, `chat`, and `admin` RBAC.
- **Recoverable message writes**: session writes use `expected_revision`; sends use `idempotency_key`; a durable operation ledger is written before Provider execution and queried through `message.status`.
- **Discoverable Runtime contract**: `runtime.info` exposes protocol, capabilities, methods, parameter schemas, result-schema completeness, deprecations, breaking changes, transports, and disabled methods. Readiness, graceful drain, and a remote administration surface disabled by default are included.
- **Persistent events and media**: tenant events have stable `event_id` and monotonic `sequence`; SSE/WS support cursor replay; multipart media is isolated by user and Agent ownership.
- **GensokyoWorld orchestration**: multiple characters share a stage and public transcript while retaining private sessions and memories. A Director chooses speakers and scene transitions. Runtime `world.*`, console operation, persistence, resume, and perspective memory projection are included.
- **NoneBot2 QQ adapter**: group/private chats map to isolated Runtime tenants, with reminders, reconnect watchdog, member impressions, repeat protection, reply focus, message batching, status, and quota commands.
- **Character internal state**: eight-dimensional emotion, four-dimensional speaking drive, proactive timing, long-term thinking, and periodic memory distillation share one pipeline.
- **Two-layer memory**: bounded working memory plus semantic-memory distillation, retrieval, CRUD, graph, decay, and capacity eviction. Adds `memory.add`.
- **Tools and knowledge lookup**: adds `fetch_url`, curated authoritative-site routing, up to two tool follow-up rounds, and group-jargon learning.
- **Providers and multimodal input**: further aligns usage reporting, final stream chunks, images, and multimodal content across OpenAI, Responses, Claude, Gemini, and compatible providers.

## Behavior Changes

- Reasoning is public by default. Clients should render `reasoning_content` separately from final `content` and apply their own visibility policy.
- WebSocket streaming returns a start acknowledgement containing `stream_id` / `generation_id` before content frames.
- `session.list` and `session.messages` return cursor-paginated result objects.
- HTTP/WS disables `runtime.shutdown`, `dependency.install`, and character-package import/export by default; enable remote administration only on a trusted management network.
- Proactive speech uses ThinkEngine four-dimensional scoring plus a threshold; forced fallback and accumulation are removed.
- Episodic memory and model-invoked memory tools are retired; semantic retrieval and periodic distillation own long-term information.
- Display and memory cleaning are separated and remove full-line stage directions, fake speaker prefixes, separator lines, and internal DEBUG category residue.
- GenerationGuard binds long-term thinking, distillation, and turn requests to a session generation so late tasks cannot write into a newer session.

## Reliability and Security Fixes

- Fixes duplicate generation under concurrent identical keys, successful long-session sends marked failed, operations stuck pending after disconnect, and rollback overwriting older messages.
- Fixes tenant-creation TOCTOU, deletion during active work, LRU eviction while waiting on a lock, and one corrupt tenant taking down the process.
- Fixes cross-session SaveCoordinator callbacks, persistence workers wedged after failure, interrupted World paragraphs not being committed, and proactive World paragraphs not being saved.
- Blocks SSRF trailing-dot, short-form, decimal, hexadecimal, and IPv4-mapped address variants.
- Fixes WebSocket heartbeat cleanup, subscription leaks, synchronous file/subprocess work blocking the event loop, and fire-and-forget tasks being garbage-collected.
- Fixes final usage stream chunks being skipped, multimodal completion checks raising `TypeError`, and second-round tool calls being dropped.
- Tightens event/log redaction to exact sensitive names and suffixes so credentials remain protected without erasing normal metering fields.

## Deprecated (Still Compatible)

- Non-namespaced legacy RPCs such as `init`, `send_message`, and `list_sessions` remain callable. New clients must follow `runtime.info.method_specs[].replacement` to namespaced methods.
- `initiative_timer.hesitation` / `initiative_timer.hesitation.set` return retirement payloads and no longer mutate Agent state.
- The earliest removal version for every currently retained legacy RPC is Runtime protocol `3.0.0`. No legacy method is removed in this release.

## Removed or Breaking Changes

Runtime protocol moves from `1.1.0` in the previous public release to `2.2.0`; the major version changes from `1` to `2`. Protocol-1 clients must migrate at least these behaviors:

1. RPC failures use top-level `ok=false` and top-level `error`, not `result.ok=false`.
2. WebSocket streams add a start acknowledgement.
3. `runtime.info.protocol` identifies the shared RPC protocol; discover concrete transports from `runtime.info.transports`.
4. Reasoning is public by default.
5. Network Agent/session operations require explicit `agent_id` and `session_id`.
6. Session writes require `expected_revision`; sends and status queries require a stable `idempotency_key`.
7. `session.list` / `session.messages` return paginated objects instead of bare lists.

Legacy `initiative_timer.fallback_*`, `hesitation_*`, drive-accumulator, and `memory.episodic_*` settings are retired with migration diagnostics. The `remember`, `recall`, and `update_memory` model-invoked tools are removed.

## Client Migration

1. Call `runtime.info` after connection and reject an unknown `protocol_major_version`; this release reports `2`.
2. Discover support through `methods`, `method_specs`, `capabilities`, and `active_transport.disabled_methods` instead of hard-coding availability.
3. Initialize or list an Agent and persist `agent_id`; persist each `session_id` and latest `revision`.
4. Include `expected_revision` on session writes. On conflict, reread authoritative state before merging.
5. Generate a 1-128 character `idempotency_key` for each send and reuse it for network retries.
6. Read the WS start acknowledgement first. After disconnect, query `message.status` and then `session.messages`; do not attempt token-stream resume.
7. Consume paginated session/message results and render reasoning separately from final content.

See [`docs/en/runtime_api.md`](../runtime_api.md) for the complete contract.

## Data Migration

- Session schema moves from `1` to `2`. Legacy sessions gain `revision`, stable `message_id`, and per-message revision on first read while unknown extension fields are preserved. The pre-migration file is retained as `.bak`.
- Memory remains schema `2`; config, session export, and character package remain schema `1`.
- Adds independent world session schema `1`.
- Unknown newer schema versions are never silently downgraded or overwritten; Runtime reports diagnostics and preserves the source file.

## Installation and Dependencies

- Minimum Python remains 3.14.
- Core `ayafileio` minimum rises to `1.4.8`.
- Adds optional extra `nb2`: `nonebot2[fastapi]>=2.4` and `nonebot-adapter-onebot>=2.4`.
- Wheel and sdist now include templates, characters, scenes, and documentation; source checkouts and installed packages use the same resource lookup behavior.
- This release publishes GitHub wheel and sdist only. It does not upload to PyPI or bundle HakureiTerminal.

## Known Limitations

- The default file backend supports single-node remote multi-user operation and does not claim multi-node consistency. Multi-node service requires a database and shared object storage.
- Token streams do not resume across connections; recover through operation status and authoritative session state.
- Provider SDKs remain optional extras; the wheel does not force-install every Provider.
- The project remains Alpha. Protocol 2 changes should prefer compatible additions; removing retained legacy RPCs will require protocol 3.
