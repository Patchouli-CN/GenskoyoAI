# GensokyoAI v2026.8.4.0 Changelog

Release date: 2026-08-04

## Summary

The "external attention" family grows: a group-jargon miner lets characters
gradually learn each group's slang; `fetch_url` plus curated knowledge sites
lets characters look up domain knowledge from authoritative sources instead of
guessing or relying on flaky scrapers; the OOC pipeline had five logic holes
fixed across two live review rounds; and the root cause of "searched but never
replied" (second-round tool calls being dropped) is fixed.

## New Features

- **Group jargon miner (AttentionThings `jargon` kind)**: per group, after a
  message buffer fills (default 40 lines) and a cooldown passes (default 30
  min), an LLM pass picks out group-specific words/memes an outsider wouldn't
  understand and writes them into that group's semantic memory (topic = the
  term, content marked "possibly unverified" against hallucinated definitions).
  When the term comes up again, its meaning is injected by the existing
  retrieval pipeline — the character gradually "gets" the group. Never mined in
  private chat; known topics aren't relearned.
  Config: `GSK_NB2_JARGON` (default on) / `GSK_NB2_JARGON_MIN_LINES` /
  `GSK_NB2_JARGON_COOLDOWN`.
- **`fetch_url` tool + curated knowledge sites**: built-in web fetch tool
  (aiohttp; SSRF validation, HTML stripping, 4000-char truncation). Sites
  listed in `tool.web_search.knowledge_sites` (site + desc) are rendered into
  per-round tool instructions; the model routes itself — domain questions
  (characters/lore/settings) go to `fetch_url` on the authoritative site
  (MediaWiki searchable via api.php), unrelated topics go to `web_search`.
  Fetch failures return a clean message to the model; URLs/timeouts and other
  technical details only go to logs (they will never be read aloud by the
  character). Enable by adding `"fetch_url"` to `tool.builtin_tools` and
  configuring knowledge_sites (e.g. thbwiki.cc).
- **`memory.add` RPC**: writes one semantic memory into the current session
  (adapter knowledge-learning channel; existing topic name assigns directly).
  Runtime protocol version is now **2.2.0** (major stays 2, purely additive —
  no client migration needed).
- **Tool-call detail logs**: `N tool calls detected: names` (INFO), per-call
  DEBUG lines with `name(arguments)` and a truncated success preview; full
  payloads remain at TRACE.

## Behavior Changes

- **OOC exhaustion no longer ships an unjudged rewrite**: all judged versions
  are score-tracked; when retries run out, the lowest-scored version wins
  (possibly the original — "rewritten worse" no longer ships). A final
  over-threshold round no longer triggers a rewrite nobody could judge (saves
  one call). Precheck rewrites now go through the bounded judge loop too.
- **Hard vetoes count as the worst score**: versions flagged
  `copied_inner_monologue` score 1.0 for best-of fallback purposes and can no
  longer be resurrected by the lowest-score fallback.
- **Merged multi-speaker replies no longer misjudged by OOC**: the current
  speakers are passed to judge/rewrite — the judge knows "replying to several
  people with multiple @s is expected, not templating", and the rewrite is
  hard-constrained to "keep a response for every speaker".
- **Self-replay precheck**: a candidate that repeats the character's own recent
  reply (near-identical overall, or containing a verbatim chunk — name-swapped
  recitals included) is rewritten as "answer it as a new question". Short
  replies are exempt.
- **Tool follow-up rounds**: when the model wants to search again after seeing
  results, second-round tool calls now execute (up to 2 rounds), fixing "searched
  but never replied" (previously the second round was dropped, leaving an empty
  reply that triggered the fallback message).
- **OOC judgment skips World turns and live-streamed responses**: stage
  narration is no longer rewritten by chat-style standards; already-delivered
  stream text is no longer rewritten (avoiding a "what the user saw ≠ what the
  character remembers" fork).

## Fixes

- **Idempotency ledger marking successful generations as failed in long
  sessions** (high-severity regression): after working-memory trimming, the new
  assistant message fell below the index watermark and every success was
  recorded failed (no stamping, retries erroring). The new assistant is now
  located by content.
- **Persistence chain, three fixes**: `SaveCoordinator.reset()` reconnected on
  session switch (new sessions no longer have autosaves silently skipped by the
  old session's baseline); save completion callbacks are claimed per session
  (late results from the old session no longer clear the new session's pending
  flag); a PersistenceWorker fallback-path crash (which could wedge the pending
  flag forever).
- **SSRF encoding-variant bypass**: trailing-dot / short-form / decimal / hex /
  v4-mapped spellings of `169.254.169.254` were all allowed, reaching cloud
  metadata; they are now normalized (inet_aton semantics) before checking.
- **knowledge_sites crashing on load**: msgspec constructors don't deep-convert
  list items, leaving dicts that broke attribute access in instruction
  rendering; items are now explicitly converted.
- **4 red tests**: SSRF tests aligned with the template provider change;
  config-dir tests updated for moved imports.

None. Runtime protocol 2.2.0 (major 2) is purely additive.

## Data Migration & Upgrade Notes

- No schema version changes; session and semantic-memory formats unchanged.
- To enable fetch_url: add `"fetch_url"` to `tool.builtin_tools`; once
  `tool.web_search.knowledge_sites` is configured, the character starts
  preferring authoritative sites.

No new dependencies (fetch_url uses the existing aiohttp; jargon/ddgs reuse
current dependencies).

- Return fields: no changes.

## Known Issues

- "Doesn't always search when asked": main-model tool discipline is still not
  100% reliable (hardened knowledge-site routing instructions shipped; a more
  thorough "lookup attention proxy-search" design is being evaluated).
- The ddgs keyless scraper can't reach some backends (e.g. startpage) from some
  networks; occasional single-engine errors are expected and covered by its
  multi-engine fallback.
